# INV-142: Show which items need reordering

## Why
Warehouse staff can't tell at a glance which items are running low: today they compare the Stock and Reorder columns in their heads for every row. The purchasing team's spreadsheet pulls from the API and has to repeat the same comparison.

## Scope
**In scope**
- A stock status on every row of the item list (Out of stock / Low / OK), distinguished by colour as well as text.
- A "Needs reordering" filter on the item list.
- A `stockStatus` field on every item in API responses.

**Out of scope / does not change**
- The database schema: the status is derived, never stored.
- Existing JSON fields and their meaning. `stockStatus` is added, nothing is renamed or removed.
- The Stock and Reorder columns keep showing `quantity` and `reorderLevel`.
- No new endpoint.

**Reuses**
- `InventoryItem.stockStatus()` (returns `OUT_OF_STOCK`, `LOW` or `OK`). Do not add a second calculation.

## Scenarios
### Domain
- **WHEN** an item has quantity 0 and reorder level 10 **THEN** `stockStatus()` is `OUT_OF_STOCK`
- **WHEN** an item has quantity 10 and reorder level 10 **THEN** `stockStatus()` is `LOW`
- **WHEN** an item has quantity 3 and reorder level 10 **THEN** `stockStatus()` is `LOW`
- **WHEN** an item has quantity 11 and reorder level 10 **THEN** `stockStatus()` is `OK`
- **WHEN** an item has quantity 1 and reorder level 0 **THEN** `stockStatus()` is `OK`

### API
- **WHEN** a client calls `GET /api/items` **THEN** every item has a `stockStatus` field with value `OUT_OF_STOCK`, `LOW` or `OK`, matching its classification
- **WHEN** a client calls `GET /api/items/{id}` **THEN** the item has a `stockStatus` field matching its classification
- **WHEN** a client creates (`POST`) or updates (`PUT`) an item so its quantity crosses the reorder level **THEN** the response's `stockStatus` reflects the saved quantity
- **WHEN** a client reads any item **THEN** all fields that existed before (`id`, `partNumber`, `name`, `category`, `storageLocation`, `quantity`, `reorderLevel`, `description`) are still present and unchanged

### UI
- **WHEN** the item list is opened with the seed data **THEN** the row for `TRN-2N2907A` (quantity 38, reorder level 40) shows the status `Low`
- **WHEN** the item list is opened with the seed data **THEN** the row for `PCB-CTRL-100` (quantity 12, reorder level 4) shows the status `OK`, Stock `12` and Reorder `4`
- **WHEN** a user adds an item with quantity 0 and reorder level 5 **THEN** its row shows the status `Out of stock`
- **WHEN** `Out of stock`, `Low` and `OK` rows are all visible **THEN** the three statuses have three different colours
- **WHEN** the user checks `Needs reordering` with the seed data **THEN** only the `TRN-2N2907A` row is shown
- **WHEN** the user unchecks `Needs reordering` **THEN** all 12 seed items are shown again
- **WHEN** the user checks `Needs reordering` and no item is `LOW` or `OUT_OF_STOCK` **THEN** the table shows `Nothing needs reordering`
- **WHEN** the filter is on **THEN** the summary figures above the table still count all items
